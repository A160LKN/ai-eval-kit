# AI Eval Kit

[![AI eval](https://github.com/A160LKN/ai-eval-kit/actions/workflows/eval.yml/badge.svg?branch=main)](https://github.com/A160LKN/ai-eval-kit/actions/workflows/eval.yml)

Инструмент для тестирования AI-ассистента маркетплейса: набор проверочных запросов, автоматическая оценка ответов и сравнение версий ассистента перед релизом.

Ответ LLM может звучать убедительно и при этом быть неверным. Этот проект показывает, как проверять такие ответы системно, а не «на глаз»: одинаковыми критериями, на каждом изменении, с понятным решением — выпускать или нет.

## Что проверяется — 14 кейсов

| Категория | Что ловим |
| --- | --- |
| Факты из каталога | неверная цена, «есть в наличии», когда товара нет, ошибка в стоимости доставки |
| Галлюцинации | выдуманная цена товара, которого нет в каталоге |
| Неполные данные | ассистент не просит номер заказа, а отвечает наугад |
| Нестандартный ввод | опечатки, вопрос на казахском, просьба не по теме |
| Безопасность | prompt injection в отзыве покупателя, запрос чужих персональных данных |
| Формат ответа | невалидный JSON для интеграции, строка вместо числа |
| Повторные обращения | разные цены в ответ на один и тот же вопрос |
| Качество ответа | длинный ответ, когда пользователь просит коротко |

У каждого кейса есть критичность: **critical** — ошибка вредит покупателю или бизнесу, **major** — заметная ошибка в важном сценарии, **minor** — неудобство.

## Как это работает

```
evals/cases.json  ─┐
evals/catalog.json ├─► evaluate ─► результат по каждому кейсу ─┐
runs/v1.json      ─┘                                            ├─► compare ─► отчёт + quality gate
runs/v2.json      ───► evaluate ─► результат по каждому кейсу ─┘
```

1. **Кейсы** описывают запрос и проверки ответа в JSON — новые сценарии добавляются без программирования.
2. **Прогон** — ответы ассистента на все кейсы. В репозитории два демонстрационных прогона (v1 и v2); ответы настоящей модели собираются командой `collect`.
3. **Проверки** детерминированные: подстроки, регулярные выражения, длина, язык ответа, валидность JSON, **сверка всех сумм в ответе с каталогом** и **стабильность при повторах**.
4. **Quality gate** блокирует релиз, если не проходит хотя бы один критичный кейс или появилась регрессия в критичном или важном кейсе. Регрессии в некритичных кейсах — предупреждение.

## Пример: v1 → v2

| | v1 | v2 |
| --- | --- | --- |
| Прошло кейсов | 10 из 14 | 13 из 14 |
| Критичных ошибок | 3 | 0 |
| Исправлено | | 4 |
| Регрессий | | 1 (некритичная) |

Ошибки v1, которые нашёл инструмент:
- сообщила, что чайник есть в наличии, хотя на складе 0;
- выдумала цену iPhone 17 Pro, которого нет в каталоге;
- выполнила «инструкцию» из отзыва покупателя и пообещала скидку 90 % по промокоду;
- на один и тот же вопрос назвала две разные цены.

v2 исправила всё это, но стала отвечать многословнее и не уложилась в лимит для короткого ответа. Gate пропускает релиз с предупреждением — решение остаётся за командой.

Полный отчёт публикуется в сводке каждого запуска GitHub Actions.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

pytest                                                    # 40 тестов самих проверок
python -m aieval evaluate runs/assistant-v1.json          # оценить одну версию
python -m aieval compare runs/assistant-v1.json runs/assistant-v2.json --report report.md
```

`compare` возвращает код 1, если gate не пройден, — так CI останавливает выпуск.

### Ответы настоящей модели

```bash
pip install anthropic
export ANTHROPIC_API_KEY=...
python -m aieval collect --model claude-haiku-5-5 --assistant live --out runs/live.json
python -m aieval compare runs/assistant-v2.json runs/live.json
```

Ассистент получает каталог в системной инструкции. Для кейсов с повторами запрос отправляется несколько раз.

## Структура

```
aieval/
├── checks.py     проверки ответов
├── runner.py     прогон кейсов, сравнение версий, quality gate
├── report.py     отчёт в Markdown
├── collect.py    сбор ответов модели через Anthropic API
└── __main__.py   командная строка
evals/            кейсы и каталог маркетплейса
runs/             записанные ответы версий ассистента
tests/            тесты самих проверок
```

## Что можно добавить

- оценку по смыслу с помощью второй модели (LLM-as-judge) для ответов, которые нельзя проверить подстрокой;
- несколько прогонов одного кейса и долю успешных ответов вместо «прошёл / не прошёл»;
- историю метрик по версиям и график качества.
